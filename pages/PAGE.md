# 解說頁的寫法

`explain` 和 `checkpoint` 的 HTML 頁共用這份。`<P>` 是這個資料夾（plugin 根目錄的 `pages/`）。頁面是一次性的：放 scratchpad，不進 repo。

## 來源

讀者靠這頁理解系統，一句錯的說明會讓他帶著錯的印象去改程式。

- 「現在怎麼運作」以**程式碼**為準，每句附 `檔案:行`。
- 「為什麼這樣做」引文件原文：需求、計畫、ADR、偏差紀錄、票的 Comments、commit，附章節或 hash。
- 文件說的和程式做的不一樣：不在正文裡挑一邊講，另列〈文件和程式對不上〉，兩邊的來源都附。
- 找不到來源的句子標 `推斷`（灰色小標籤），寫出根據什麼推的。
- 決定附**決定者**：使用者定、使用者同意（agent 提議）、Agent 定、不明（當時沒記）。repo 有標就照標，沒標的照原文判斷，判斷不了寫不明。

## 圖

用 Mermaid，只用 `flowchart`、`sequenceDiagram`、`stateDiagram-v2`、`classDiagram`、`erDiagram` 這幾種。

- 有先後順序的過程（誰先呼叫誰、等多久、重試幾次）用 `sequenceDiagram`；`flowchart` 畫結構和分岔。
- 一張圖 ≤ 15 個節點；更大就拆成總圖加分圖。
- 節點標籤加雙引號，寫使用者看得懂的話；程式名稱放括號裡，例如 `A["送下載（submit_job）"]`。
- 每張圖下面一兩句說這張圖在講什麼、從哪裡讀起。

圖寫在 `<pre class="mermaid">` 裡，不用自己載入 Mermaid，〈組頁〉會放。

## 組頁

頁面寫成 `<名稱>-src.html`，再組成單一檔案 `<名稱>.html`：

```
python <P>/scripts/build.py <名稱>-src.html
```

Orca 從另一台機器打開工作區的 HTML 時走隔離預覽：對外請求一律被擋，超過 512 KiB 的檔不顯示。所以頁面只要從外部載入任何東西（CDN 的 script、樣式、字型、圖片）`build.py` 就拒絕產出；有圖時，它用本機的 Chrome 或 Edge 無頭跑 Mermaid，把畫好的 svg（淺色、深色各一份）寫進頁面，不帶任何 script。圖畫不出來、找不到瀏覽器、或組好的頁超過 512 KiB 時，退出碼是 1。超過 512 KiB 就拆頁或刪圖。改頁面時改 `-src.html` 再重組；組好的檔案是一大串 svg，不要直接讀或改。

## 外觀

照 [TOKENS.md](TOKENS.md)。版面是一般文章：70ch 文字欄、標題和留白分段，表格只用在真正逐列比較的地方。

## 寫法

讀者是 repo 的主人，常常不是這個領域的專家。

- 頁面用使用者對話的語言。
- 先講效果，再講機制：「你按下確認之後，系統會…」，再說哪個模組做的。
- 名詞用 repo 名詞表的詞。名詞表的詞，和讀者不一定認得的技術詞（套件、工具、錯誤碼、測試種類），第一次出現都附一句白話解釋。
- 變化寫成「以前…，現在…」。
- commit 在正文裡用它代表的時間點稱呼（「M0 驗收時的 main」「今天的 main」），hash 放進來源標籤。
- 一個列表項目講一件事；幾件小事就拆成子列表。
- 要讀者追認、歸類或略過的清單逐條列全，條數多就放進 `<details>`，`<summary>` 寫條數。讀者只能對看得到的條目負責。

## 交出前

1. **核對**：把整頁和頁上引到的來源交給一個沒看過你結論的子代理（審查用的模型），回報兩種句子：附了來源卻和來源對不上的；講了事實、預估或因果，卻沒附來源也沒標 `推斷` 的。改掉、補來源，或改標 `推斷`。頁尾寫核對紀錄：核對幾句、改了幾句、改標 `推斷` 幾句。
2. **渲染**：`build.py` 退出碼 0、印出「N 張圖都畫出來了」就算過。它說找不到 Chrome 或 Edge 時，產出的頁改成內嵌整份 Mermaid（約 3.6 MB，Orca 遠端預覽打不開，跟使用者說要在本機瀏覽器看），改用瀏覽器自動化工具檢查（下面以 playwright 為例）：
   - playwright 不開 `file://`，在 scratchpad 用背景模式開 `python -m http.server <port> --bind 127.0.0.1`。
   - 打開組好的頁，確認每張圖都畫成 svg、畫面文字（`document.body.innerText`）沒有 `Syntax error`。不要搜原始碼：內嵌的 Mermaid 自己就含這個字串。
   - 截圖的檔名用 scratchpad 的完整路徑。
   - 檢查完關掉 server；playwright 在工作目錄建了 `.playwright-mcp/` 的話刪掉。
3. 用預設瀏覽器打開組好的檔案（macOS `open`、Windows `start`、Linux `xdg-open`），在對話給它的完整路徑。

完成條件：核對回報的每一句都處理了，頁尾有核對紀錄；每張圖都畫得出來（`build.py` 退出碼 0，或 playwright 退路檢查過）；這次開的 server 都關了。
