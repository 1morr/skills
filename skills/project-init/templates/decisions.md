# 決策紀錄

進行中里程碑裡不是做票時定的決定，一條一行，只追加；做票時定的留在票上（`python3 scripts/ticket_notes.py <里程碑的目錄名>` 印出來）。已驗收里程碑的在 `docs/archive/<里程碑>.md` 的〈決定〉。現在的做法寫在 brief、`ARCHITECTURE.md`、ADR 與 spec；這裡記的是「誰在什麼時候定了什麼」，並連到寫著細節的地方。

## 寫法

- 一條一行：`- <日期> <里程碑>（<決定者>）：<決定，一句>。<細節在哪：ADR、票、brief 的章節>`，整行不超過 200 字元。
- 決定者三選一：`（使用者定）` 使用者自己定的、`（使用者同意）` agent 提議而使用者同意的、`（Agent 定）` 使用者沒看過的。
- 要記的：訪談與規劃時定下的、推翻先前決定的、做票時在兩種做法之間選的。照票面與文件做、沒有選擇的不記。
- 誰記在哪：訪談、規劃、開工、驗收票的 session 記在這裡；做票的 session 記在票的 Comments，寫成 `決定：<一句>（<決定者>）`，不超過 160 字元（`AGENTS.md`〈每個 session 的流程〉）。
- 需要寫理由、難回頭的架構決定另寫 ADR，在這裡佔一行並連過去。
- 推翻舊的一條時加新的一條，寫明推翻哪一條的日期；舊的那條留著。
- 里程碑驗收時，標著它的那幾條搬到 `docs/archive/<里程碑>.md`，步驟在 `docs/agents/milestone.md`〈驗收票〉；還沒有里程碑時定的（標「框架」這類）跟第一個里程碑一起搬。本檔只留進行中的。
- `python3 scripts/check_docs.py` 強制〈紀錄〉每條的日期開頭、一個決定者、長度。
