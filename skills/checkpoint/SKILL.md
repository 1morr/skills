使用者是 repo 的主人，但常常不是這個領域的專家，很多做法是照 agent 的建議走的。這個 session 讓他在拆下一個里程碑前**放心**：知道剛做完的那段做了什麼、對不對、留下什麼，也知道下一段的打算、同意了才開工。

參數：$ARGUMENTS

產出是一頁臨時的回顧頁（寫法見 [`../explain/PAGE.md`](../explain/PAGE.md)）、對話，以及寫回 repo 原有文件的定案。repo 裡不另建回顧或導覽文件。

## 1. 範圍與來源

1. 讀 CLAUDE.md / AGENTS.md，找出計畫、進度、票、決定紀錄（ADR、偏差紀錄）、名詞表放在哪裡，以及 session 結尾的規定。
2. 定範圍：
   - 參數是里程碑：它的 spec、票、進度紀錄（含封存檔）；commit 範圍從它第一個 commit 的前一個到驗收 commit。
   - 參數是 commit 範圍：照用。
   - 沒給：進度紀錄裡最近驗收的里程碑；看不出來就問使用者。
3. 找**下一段**：計畫裡排在後面的里程碑（已開工就讀它的 spec 和票），或使用者說要做的事。
4. 參數裡使用者的問題、用起來遇到的問題，記下來，第 5 步放在回顧頁最前面回答。

完成條件：`git log --oneline <範圍>` 列出的正好是這一段；回顧和下一段要讀的文件列成清單。

## 2. 回顧

範圍大就分給子代理，每個帶回附來源的摘要。逐項寫：

- **做了什麼**：照使用者感受得到的效果分組（功能、行為、介面），一組一句「以前…，現在…」。
- **為什麼**：引 spec、票、決定紀錄的原文。
- **對不對**：
  - spec 的驗收逐條對到證據（測試、驗收紀錄、截圖）。
  - 列出計畫有但沒做的、做了計畫外的、推翻計畫卻沒記偏差的。
  - 挑這段的關鍵機制對照現在的程式碼，文件說的和程式做的不一樣就列出來。
  - 跑 repo 的全部檢查和測試，貼結果。
- **遺留**：沒過的驗收、使用者接受的未達標、延後的項目、各票 Comments 裡沒處理的發現、新加的 TODO。每項寫**誰接手**（票、里程碑）；沒有就標「沒人接」。
- **決定**：這段時間的決定，每條標**決定者**：使用者定、使用者同意（agent 提議）、Agent 定、不明。

完成條件：每張票、每條驗收、每項遺留都歸了位；「沒人接」和「Agent 定」另外列出。

## 3. 下一段

- 要做什麼、為什麼現在做（引計畫原文）、打算怎麼拆、會碰到哪些現有模組，附流程圖或架構圖。
- 風險和沒定的事：計畫裡有兩種讀法的地方、spec 和票說法不同的地方、門檻或驗收條件實際上量得出來嗎、依賴卻沒查證的外部事實、和第 2 步的遺留撞到的地方。

完成條件：下一段每張票（或每個工作項）都說得出要做什麼和會碰到的模組。

## 4. 回顧頁

照 [`../explain/PAGE.md`](../explain/PAGE.md) 寫一頁，依序：

1. 使用者在參數裡問的事，直接回答。
2. **要你確認的事**：一題一行，附你的建議和理由。
3. 做了什麼、為什麼，附這段改動後的架構圖或流程圖。
4. 對不對：驗收對證據、偏差、文件和程式對不上的地方、檢查和測試結果。
5. 遺留，「沒人接」排最前面。
6. 決定，「Agent 定」排最前面。
7. 下一段的打算和風險。

完成條件：照 PAGE.md〈交出前〉核對和渲染過。

## 5. 對話

在對話裡貼「要你確認的事」（一題一行，同回顧頁）和回顧頁的完整路徑，然後：

- 回答追問，附來源。問到某個功能或機制怎麼運作，照 [`../explain/SKILL.md`](../explain/SKILL.md) 的第 2 步追過程式碼再答；答案大到要圖就另出一頁解說頁。
- 使用者定了新決定或改了主意：記下，第 6 步寫回。
- 問一次要不要做**理解檢查**：出 2–3 題「如果 X 發生，系統會怎樣」，答錯的地方再講一次。

使用者說可以了（例如「照建議」）才往下。

## 6. 寫回

1. 確認的事和對話定下的決定，寫進 repo 原本記錄它們的地方（照 CLAUDE.md：spec、票、計畫、需求文件、ADR、偏差紀錄），標決定者。遺留掛到接手的票上。
2. 推翻計畫卻沒記的偏差補記，註明是回顧時補的。
3. 照 repo 的規定 commit；有進度紀錄就加一列。
4. 照 repo 的 session 結尾規定給下一步的指令：下一段還沒拆票就是拆票指令，已拆好就是第一張票。

完成條件：每題「要你確認的事」都能指出寫回到哪個檔案；已 commit。
