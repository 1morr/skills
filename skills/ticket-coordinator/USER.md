# 等使用者決定、使用者插話

ticket-coordinator 的分支：SKILL.md〈真的卡住〉要把題目留給使用者時、worker 問到要使用者拍板的題時，和使用者在隊列進行中插話時照這份。`<O>` 的定義在 SKILL.md。

## 隊列停下時

隊列卡住時，把要使用者決定的事寫進 repo，照專案指令檔的格式（下面是 `project-init` 骨架的寫法）：

- 卡在某一張票：在主目錄那張票的 `## Comments` 加一行 `等使用者：<題目>`，題目寫成沒讀過票也看得懂的話。
- 卡在整個隊列（額度讀不到、主分支壞了）：`docs/progress.md` 加一列，「下一步」寫 `等使用者：…`。

照 SKILL.md〈協調者自己的 commit〉commit，再照 `push-ci.sh` 推上去。使用者回答後，在那一行下面記 `決定：<一句>（使用者定）` 並 commit；worker 下次跟上主分支時會拿到。

## 等使用者拍板

SKILL.md〈每張票〉第 2 步挑出要使用者拍板的題時照這節。題目照 COORDINATOR.md〈回報〉寫，背景、選項、建議照 worker 的題目，偏離已定文件的點明是哪一句。

- **使用者在場**：把題目寫在一般回覆裡，結束回合等他回。回合結束了，他中途離開時其他票的 orchestration 通知照樣叫得醒你。
- **使用者不在場**：只擱置這張票，其他票照跑。
  1. worker 保持原狀（等待 `reply`），ledger 把它標 blocked、記下 `msg_id` 與題目。
  2. 照〈隊列停下時〉在主目錄那張票加 `等使用者：<題目>`；它下面的決定由 worker 寫，見下一條。
  3. 會撞的票一起擱置：`Blocked by` 它、要用它的產出、或改到同一區程式碼的。其餘的照 SKILL.md〈每張票〉跑，總表把這一題放最前面。
- **他回答之後**（當場或回來時）：用 `orca orchestration reply --id <msg_id> --body "<答案>"` 一次回完他的選擇、決定者和專案規則要的後續（照 COORDINATOR.md〈對話透明化〉在對話寫一行摘要），例如「接著播、成為目前那首。使用者本人選的，記（使用者同意）；這題偏離 brief『臨時播放照舊版』，改 brief 的那句草稿先給使用者看，確認後同一個 commit 改」。他選了建議的那項記使用者同意，選了別項或自己寫答案記使用者定。
  - 擱置過的票，答案再加一句「跟上主分支後，把決定寫在票上 `等使用者：` 那一行下面」；ledger 改回 running，一起擱置的票接著排。

## 使用者插話

使用者會在隊列進行中問問題、要求修正。每次處理完，回到原本的等待。

- **問程式或進度**：從程式碼、票、spec、決定紀錄查出答案，每個說法附檔案路徑。你記得的不算來源；要圖或篇幅長的，建議他另開 session 呼叫 `explain` skill。
- **要改東西**，先分類並用一句話告訴他你歸成哪一類，他同意後才動：
  - **小修**：沒有要他決定的事、不推翻已定的文件、改動集中在一處、現有的測試或閘門驗得到。下面幾類要開票的，是小修就改成併進票，不開新票：
    - 有相關的票在跑：用 `orca orchestration send --to dispatch:<dispatch_id>` 把要改的送給它的 worker，叫它另成一個 commit、補測試，票的 `## Comments` 記一行 `變更：`。這張票的 code-review、閘門和 CI 一起涵蓋它。
    - 沒有：在下一張會改到那一區的票加一條驗收條件，照 SKILL.md〈協調者自己的 commit〉commit。
  - **已做完的票做錯了**（跟票面或 spec 不符）：開修復票 `<NN>b-<slug>.md`，照專案的票範本寫，驗收條件裡有一條會紅的 repro；排在下一張之前。
  - **票面本身不是他要的**（還沒做的票、spec、brief、設計稿）：這是推翻已定的決定。改那份文件，並照專案指令檔記一條決定，決定者是使用者定；被影響的票一起改，正在跑的那張用 `orca orchestration send` 把改動送給它的 worker。brief、架構、ADR 的草稿先給他看。
  - **新的要求**（不在這個里程碑的範圍）：寫進 roadmap 接手的里程碑那一節，沒人接的進 roadmap〈不排里程碑〉；他要現在就做才開票排進隊列。
- **說要離開或回來**：離開（去睡、出門）就改成不在場，回來改回在場，ledger 記下切換的時間。回來時先把擱置中的題照 COORDINATOR.md〈回報〉列給他。
- 開票、改文件照 SKILL.md〈協調者自己的 commit〉。隊列變了就更新 ledger，並把新的順序報給他。
