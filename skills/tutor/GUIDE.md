# 導讀頁與答案紙

tutor 做材料的分支：`plan.md` 寫好之後，照這份寫導讀頁和答案紙。`<S>` 的定義在 SKILL.md。「§N」是導讀頁上的段落編號，由 build 依 `<h2>`、`<h3>` 的順序產生。

## 這一頁要做到什麼

讀者在時間預算內讀完，題型表上的每一件事都做得出來。正文是你寫給這個讀者的講解，怎麼分段、每段長什麼樣，照 `plan.md` 和這份材料來定；右邊的課件欄跟著正文走，他隨時看得到你在講老師的哪一頁。

- **第一個畫面**：考什麼（考試的時間、形式、範圍）、主線、這頁怎麼讀（時間不夠先讀哪幾段）。要讀多久是你控制份量用的，頁面上不寫。
- **份量跟著輕重**：最重的題型講到會做為止，有例子、有容易錯的地方、有自測；最輕的在表上一列帶過。
- **考卷上寫什麼就教什麼**：課件上的術語、人名、組織、事件、專有的地名，每次出現都寫成「譯名（原文）」，例如「南進（Nam tiến）」，第二次、第十次也一樣，標題、重點框、點選題的理由裡也一樣；表格的格子、點選題的選項、速查卡只寫原文。讀者本來就認得的一般詞（國名、世紀、常見的城市）照讀者的語言寫。要寫在考卷上的句子給原文的寫法。
- **老師的例子優先**：課件上有例子就講它；它不夠清楚才另外補一個，並說是補的。
- **先講再用**：一個詞在講到之前就要用，原地給一句白話。這門課之前的東西，讀者不會的（學習紀錄〈讀者〉、他問過的）在用到的地方補那一點，其餘一句帶過。

## 怎麼講

形式跟著內容的形狀走。一頁裡每一段長得不一樣是對的：

| 內容的形狀 | 講法 |
| --- | --- |
| 幾個東西各有幾個屬性（國家、類型、方法） | 對照表：一列一個，欄是考試會問的屬性 |
| 先後 | 時間線，只留考試分得出先後的那幾個點 |
| 因果、論證 | 一條鏈：誰導致誰，每一環一句；申論題照老師評分看的點（論點、證據、反方） |
| 一個量、一條公式 | 先用老師的數字或幾個小整數算一次，再說每一塊在做什麼、算出來大小代表什麼 |
| 一套算法 | 步驟表：每一步拿什麼、做什麼、得到什麼；同一個例子從頭算到尾 |
| 該用哪一個（方法、檢定、模型） | 判斷的線索：題目出現哪幾個字、資料長什麼樣，就用哪個 |
| 一個名詞 | 一句話是什麼，加上考試拿什麼認它、最容易和誰搞混 |
| 一張圖、一份軟體輸出 | 看哪裡、讀出什麼、下什麼結論 |

每段寫完問自己：讀者帶著這一段進考場，那一題答得出來嗎？答不出來就還缺；和哪一題都無關就刪。

算題再加三條，數字錯了整頁就不能信：

- 公式寫出來再代數字：公式一行、代入一行，算出來的數標出來（〈元件〉的 `.calc`）。
- 每個數字和結論都由計算腳本產生（〈答案紙〉）。
- 題目先讓讀者自己做：做法和答案收在 `details.answer` 裡，一小題一個。

## 課件欄

找完材料就先把這個範圍的每份課件做成圖，在原始檔的資料夾跑：

```bash
DECK="uv run --no-project --with pymupdf --with pillow python <S>/deck.py"
$DECK slides L20=<Lecture 20 的 pdf> L21=<Lecture 21 的 pdf>
```

代號用讀者認得的短名（`L20`、`T6-Summary`、`Eg`）。它寫出每一頁的圖、`slides/slides.json` 和要翻的 `slides/zh.json`；譯文填好再跑一次就有翻譯圖（SKILL.md〈同時開工〉）。參數和檔案格式寫在它開頭。

導讀頁這樣接上課件：

```html
<body data-slides="slides/slides.json">
<h2 data-slide="L20 p.25-28">Reid 把亞洲民族主義分成哪四型？</h2>
<p data-slide="L20 p.28">三個國家各是哪一型……</p>
<tr data-slide="L20 p.29; L22 p.6" data-key><td>前身表</td><td>旗子是殖民者；沒有旗子的泰國沒被殖民</td></tr>
```

- `data-slide` 寫在**開始講那一頁的元素**上（標題、段落、表格的一列）。讀者捲到那裡，課件欄就走到那一頁，直到下一個 `data-slide`。一段講好幾頁寫範圍，同一張圖在兩份課件都有就用 `;` 列出來。
- `data-key` 標出必記的頁（`plan.md` 列的），寫在只指那一頁的元素上：寫在一個範圍上，範圍裡每一頁都會變成必記。必記的頁在正文要有一句：看到這張圖要認出什麼、考試會怎麼問它。
- 課件上的字不用抄進正文、也不用逐句翻：讀者右邊就看得到，按一下換成翻譯。正文講的是這一頁在說什麼、哪幾個字會考、它和前後怎麼接。
- 課件只給一半的地方（白色字、上課才講的）在正文補上，說明課件上是空白。

build 會印「沒講到」的頁和必記的頁數：對照 `plan.md`，沒講到的裡面沒有題型表出處列的頁，必記的頁數和計畫列的一樣。

**正文裡另外放圖**只在讀者要盯著某一小塊看的時候：統計表上要查的那一格、輸出表上的那個數字、圖上的那條線。用 `<S>/crop.py`（用法在它開頭）截那一小塊，`--box` 畫紅框、`--mark` 標出列與欄，截完用 Read 打開確認框對準了；放在 `<figure>` 裡，`<figcaption>` 寫出處的檔名頁碼。

## 速查卡和題型表

每份導讀頁都有一張速查卡 `<div class="cheat">`：讀者考前只看這一張，考前速查會把它原樣搬過去。放在哪由你定（講解之前當地圖，或最後當總結）；頁眉的「速查卡」隨時在旁邊打開它。卡上依序：

1. **題型表** `<table class="types">`：`plan.md` 題型表的每一列。`<tr data-type="acf-read">` 寫那個英文小寫代號，練習頁、模擬卷、學習紀錄用它對回這一列。答案要靠讀圖或讀軟體輸出的題型再寫 `data-reads="figure"`，練習頁這個題型的題目就必須附圖。欄位是「看到什麼題目 → 怎麼答 → 講它的 §N」。第一欄寫考卷上認得出這個題型的線索：老師的原文字眼（括號寫讀者的語言），和資料的給法。遮住後面只看第一欄，分得出它和表上其他每一列。
2. **容易搞混的**（有才寫）：線索重疊、會套錯的每一對，各由哪幾個字分開。
3. **要背的**：公式、配對、年代、判斷的門檻。名詞後面帶幾個字的意思：時間不夠、只讀這張卡的人也配得出來。考場會發公式表時（SKILL.md〈找材料〉第 7 步）寫「公式（考場會發）」。

每個小標用 `<h4>`。

## 元件

樣式備好了這些，用得到才用；沒列到的直接寫普通的 HTML（表格、清單、`<pre>` 畫的示意圖都有樣式）。框的名字由樣式加上，內文從內容寫起。

| 寫法 | 是什麼 | 什麼時候用 |
| --- | --- | --- |
| `<div class="summary">` | 黃底的重點框，名字是「重點」，`data-label="這題記住"` 可以換 | 這一段讀完要帶走的那一兩句。整頁唯一整塊上色的東西，一段最多一個 |
| `<dfn>譯名（原文）</dfn>` | 藍色螢光筆的名詞；頁尾自動產生名詞表，照原文排 | 考試會考的術語第一次出現 |
| `<div class="def">` | 上下兩條線的定義框。裡面可以加有名字的格子，一格一個 `<p class="…">`：`test` 怎樣才算、`yes` 是、`no` 不是、`how` 怎麼算、`big` 大代表、`small` 小代表、`when` 什麼時候用、`io` 做什麼、`without` 不用會怎樣 | 這個詞本身就是考點，一句話講不完。只寫講得出東西的那幾格；兩個要對照的框包進 `<div class="defs">` 並排 |
| `<div class="calc">` 裡 `class="formula"` 一行、`class="subst"` 一行，結果包 `<span class="ans">` | 算式：公式、代入、黃色螢光筆的答案 | 每一步計算 |
| `<details class="check"><summary>問題</summary>答案</details>` | 自測：先想再打開 | 要讀者算一次、寫一句的地方。答案寫到答不出來的人看了會做 |
| `<div class="quiz"><p>問題</p><ul><li data-ok>對的</li><li>錯的</li></ul><p class="because">理由</p></div>` | 點選題：選項每次重排，選對了出現理由 | 配對、辨認、選方法這類一眼作答的題型，可以連出很多題。錯的選項放真的會搞混的；理由只用到這裡為止教過的詞 |
| `<details class="answer"><summary>(a) 的做法和答案</summary>…</details>` | 摺起來的做法 | 例題和作業的每一小題 |
| `<div class="trap">` | 「常見錯誤」 | 有具體的錯法時，寫出錯成什麼 |
| `<p class="why"><b>問句？</b>答案</p>` | 讀者讀到這裡會問的一個問題 | 不講就會卡住的「為什麼」 |
| `<div class="sheet">` | 答案紙的樣子（白紙、襯線字） | 考卷或作業上要寫成這樣的那一段 |
| `<ul class="uses">` | 「這題用到」的清單 | 題目前面列出要用的公式和規則，後面寫 §N |
| `<p class="part">名稱<span>補充</span></p>` | 正文的大分隔，也是目錄上的一組 | 段落多到目錄要分組 |
| `<aside class="panel">` 裡每張 `<figure data-tab="Z 表">` | 頁眉的「查表」，一張一個分頁 | 整張統計表、每題都要對照的規則 |
| `<img src="原圖" data-zh="翻譯圖">` | 點圖換成翻譯 | 正文裡另外放的圖（`crop.py cut --zh`） |

- 內文寫「§3.2」就會變成連結，按了在旁邊打開那一段，讀者留在原位。
- 讀者按「只看重點」時，頁面只剩標題、`.summary`、`.def`、表格、`.trap`。每一段最該帶走的東西要落在這幾種裡，只看重點的人才不會漏掉。
- 強調只有兩種：`.ans` 標算出來的數；`<strong>` 標一段裡最該帶走的那個詞或門檻，一段最多一處。
- 公式用 MathML，Σ 的上下限、分數、根號才排得和講義一樣：`<div class="formula"><math display="block">…</math></div>`。Σ 用 `<munderover><mo>∑</mo>下限<mi>n</mi></munderover>`，分數用 `<mfrac>`，括號寫 `<mo stretchy="false">(</mo>`。變數斜體（`<i>T</i><sub>41</sub>`），多個字母的縮寫正體。
- `<h2>` 標題太長時，目錄用的短標題寫在 `data-short`。

## 組頁

```bash
python <S>/build.py guide-src.html -o guide.html
```

build 加上 § 編號和連結、左邊的目錄（讀到哪、讀過哪幾段）、頁眉、課件欄、名詞表，把圖片和樣式內嵌成離線打得開的單一檔案。會讓頁面或下游的頁壞掉的事它不產出，逐條印出原因（清單在它開頭），照訊息改到通過；常見的是表格或公式比正文欄寬：拆欄、縮短表頭，或一條公式拆成兩行。

通過後它印三行：產出的路徑、讀完大約幾分鐘、課件欄講到幾頁和沒講到哪幾頁。後兩行對照 `plan.md`（SKILL.md〈導讀頁和答案紙〉的完成條件）。

## 答案紙

還沒交的作業各做一份答案紙：一份要交的檔案，照老師的 Suggested Answers 格式寫（原文、簡潔、句型照講義），用 HTML 寫，再用 Chrome headless 印成 PDF（`--print-to-pdf`）。已交的作業照老師答案講；老師答案還沒出的標明「出了要對一次」；還沒發佈的在導讀頁寫一句，發佈後再叫用一次。

- 所有數字由一支計算腳本（`calc.py`）算出來：它只管算，把每個值寫成 `values.json`。答案紙寫成 `answer-tpl.html`，導讀頁寫成 `guide-tpl.html`，數字用 `{{名稱}}` 佔位，用 `<S>/fill.py` 填入；`values.json` 和佔位的格式寫在它開頭。
- 答案紙每一題包成一個 `part`，導讀頁用 `{{sheet:a}}` 把那一段原樣放進 `.sheet`，兩邊就一字不差（`fill.py --sheet`）。

```bash
FILL="python <S>/fill.py"
python calc.py                                                     # 寫出 values.json
$FILL values.json answer-tpl.html -o answer.html
$FILL values.json guide-tpl.html --sheet answer.html -o guide-src.html
```

- 題目本身有給、也能自己算出來的數字（表上已有的 MSE、F），在 `calc.py` 裡用 assert 對一次，對不上表示抄錯題。
- 數字由軟體算出時（Minitab 的 *r<sub>k</sub>*），用這題的資料手算其中一個給讀者看，說一句軟體就是照這個公式算的。
