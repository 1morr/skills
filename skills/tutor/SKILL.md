讀者沒上過課、沒有前置知識，看到符號和原文術語就卡住。目標有兩個：**只靠這裡的產出就學會課程的每一個考點**，以及**考試拿 90 分以上**。不用打開課件，也不用翻任何前一個 topic 或別的課的東西，照導讀頁讀完就懂每一頁在講什麼，做完練習頁和模擬卷就能自己做出老師的題目。

老師的材料是唯一標準：講義、例題答案、過去作業的 Suggested Answers、老師的統計表。課本是第二順位；網路和模型自己的知識只用來補前置知識、講為什麼、舉現實例子，而且符號和寫法要對齊老師。老師和課本不一致時照老師，並標出來。

講解和翻譯圖用**讀者的語言**：使用者指定的，否則是對話的語言。下面的例子是中文讀者讀英文課件。

參數：$ARGUMENTS

`<S>` 是 `${CLAUDE_SKILL_DIR}/scripts`。

## 選分支

- 這門課已經有 `學習紀錄.md`，或讀者貼回畫布、填答結果、說「卡在 §15」、要人帶著做：照 [COACH.md](COACH.md)，下面的步驟只在他另外要新材料時做。
- 要做材料（新的作業、topic、考試，或材料有更新）：照下面的步驟。導讀頁已經存在、材料沒變時，直接用現有的那份；之前沒做練習頁的，使用者回來要練習時補做。

## 產出

- 產出四樣：導讀頁、還沒交的作業的答案紙、練習頁、模擬卷。先交付導讀頁和答案紙，再做練習頁和模擬卷：趕時間的人不用等就能開始讀。
- 練習頁和模擬卷每次都做，只有使用者明說不要（「不用練習頁」「只要導讀頁」）才不做。不從截止日或「趕」「明天交」推斷他不要。
- 製作過程不提問。範圍不確定時自己選最可能的，寫在頁尾的維護者註解。
- 交付之後，讀者自己讀、自己做練習頁和模擬卷；他回到對話時走〈選分支〉的第一條。

## 1. 找材料，找出「怎樣才算答對」

1. 找題目原文。題目只寫「課本 Problem X」時，到課本把整題（含表格）找出來。
2. 找老師的教法：這個 topic 的講義、例題與答案、軟體輸出範例、軟體操作說明（例如 Software Menu）。考試只給輸出時，教怎麼讀輸出；作業要自己操作軟體時，導讀頁也要教選單步驟：按哪個選單、對話框填什麼、勾哪個選項，跑出來應該看到哪個數字。
3. 找老師的**答題格式**：過去作業的 Suggested Answers、In-class Exercise 答案。答案紙照這個格式寫，句型照講義寫。
4. 要查的表（t 表、F 表、常態分配表、週期表）用課程發的那份。先列出那份檔案每一頁是什麼表，翻過整份再決定查哪一張、要不要換表。
5. 讀 PDF 用文字層（`pdftotext -layout -enc UTF-8`，或 PyMuPDF 的 `get_text`）。講義可能有白色字（上課填空用），截圖上看是空白，要從文字層讀出來寫進翻譯，標明「課件上是空白，上課填的」。
6. 課本對應的章節：課件只寫名詞、沒給定義或判斷方法時，從課本找定義（記下頁碼）。老師在課件或例題列的 Further Readings、指定的課本例題，要當成範圍的一部分來教。
7. 找練習來源和**測驗的形式**：課本章末題、In-class Exercise、過去的測驗和作業。看它們怎麼給資料（表格、軟體輸出）、分幾小題、答案要寫成什麼句型，記下每一種題型。沒有測驗樣本時以作業為準；作業用軟體做、考試不能用時，考試的形式是「給輸出、要你讀」，照這個出練習和模擬卷。
8. 列**前置知識清單**：把講義和老師答案從頭讀一遍，圈出每一個「這門課之前就該會」的詞、符號和動作（例如常態分配、標準差、變異數、信賴區間、臨界值、Z<sub>α/2</sub> 的下標、查 Z 表），不管它看起來多基本。每一項之後都要在導讀頁第一次用到的地方從零教（GUIDE.md〈寫法〉第 2 條）。
9. 列**考點清單**：講義、例題、作業裡每一種「考試會要你做的事」一列（算什麼、判斷什麼、寫哪一句），寫出處的檔名頁碼。它就是題目欄的題型表（GUIDE.md〈導讀頁〉）。沒有老師明示「不考」的東西都列進去：講義上有公式、軟體輸出上有那一欄，就是會考。

完成條件：題目原文、老師的教法、答題格式、要查的表、測驗的形式，每一項都指得出檔名和頁碼；找不到的那一項寫進頁尾的維護者註解，連同你改用什麼代替。前置知識清單的每一項都對得到導讀頁的一個定義框。考點清單的每一列，之後都對得到導讀頁的一段講解、一題示範題、練習頁至少 2 題變式、模擬卷 1 題。

## 2. 範圍：整份課件，照課件順序

- topic、考試：這個 topic 的**全部**講義頁（Classnote、Summary），照頁碼順序；接著是例題；最後是**這個 topic 的作業**：作業比例題重要，因為要交、要算分，而且期末考的題型通常和作業差不多。
  - 哪些作業屬於這個 topic：看作業標題寫的 topic 或章節（例如 Assignment 3A 對 Topic 3）、題目用到的方法出自哪幾頁課件、課程大綱的週次表。In-Class Exercise 也算。
  - 每份作業的狀態從課程 repo 記錄進度的地方（例如日程表、作業資料夾的 README）和有沒有老師答案判斷：還沒交、已交、還沒發佈。
- 作業：只挑作業用得到的講義頁，但一樣是整頁、照課件順序，後面接作業題。
- 課件欄開頭放一張範圍表，摺在 `<details><summary>範圍：這個 topic 有什麼、考不考</summary>` 裡：
  - 每列：講義頁 → 這頁在回答什麼問題 → 哪一題、哪份作業用到。每一頁都照會考的規格教。
  - 老師明示不考的（課程大綱、公告、講義上的註記）才標「不考」，那一列寫 `data-evidence="出處"`。
  - 表下面列這個 topic 的作業和狀態、截止日。趕時間時，告訴讀者先讀作業用到的那幾頁。
- 給維護者看的說明（假設了什麼、哪些檔案還沒發佈）寫成頁尾的 HTML 註解。
- 講義頁寫進 `<body data-pages="...">`，例如 `"Classnote Topic 3 p.1-8"`，名稱和整頁圖的 figcaption 裡寫的一樣。例題檔不用列：每題只截自己那題。

## 3. 導讀頁和答案紙

照 [GUIDE.md](GUIDE.md)：寫法、兩欄的結構、截圖與組頁、答案紙。

完成條件：`<S>/build.py` 通過；還沒交的每份作業都有答案紙的 PDF，上面的數字都由 `fill.py` 填進去。

## 4. 練習頁和模擬卷

照 [PRACTICE.md](PRACTICE.md)。完成條件在它裡面。

## 5. 驗證

- 用計算腳本重算每個數字；題目或老師答案本身有給的，要對得上。練習題的答案也由腳本算。
- 結論（顯著不顯著、選哪個方法、在界線內還是外）也由腳本判定，再填進頁面，不手寫：比大小最容易寫反。
- 查表值要對照截圖上框住的那一格。
- `build.py` 通過。
- 用瀏覽器自動化工具打開導讀頁，在寬螢幕（≥ 1100px，兩欄並排）和窄螢幕各看一次：圖片和翻譯圖有顯示、點圖能切換、公式排得和講義一樣、右欄的 § 連結能讓左欄跳過去、「回到剛才」能回到跳之前的位置、「展開全部做法」「查表」「放大」有作用、工具列跟著捲動顯示現在的段落。每一欄各截一張圖自己看：不讀字，只看哪裡最顯眼，應該是標題、重點框、螢光的答案，不是截圖。答案 PDF 也打開看一次。
- 練習頁和模擬卷照 PRACTICE.md 的完成條件。
- **零基礎讀者驗收**：你讀過材料，看不出哪裡沒講。開一個沒看過材料的子代理（`model: "opus"`），只給它組好的導讀頁、練習頁、模擬卷的路徑和課程發的統計表，不給課件、答案檔和你的筆記。要它扮演沒上過課的學生，回報三樣：
  1. 導讀頁上每一個沒先定義就用到的詞或符號，和它出現的 §。
  2. 右欄每一題只讀那一題（不看左欄）做不做得出來，缺什麼。
  3. 閉卷做完模擬卷，再對範本答案：每題自評幾分、卡在哪一步、是導讀頁哪裡沒教到。
  回報的每一項都補進導讀頁（定義框、「為什麼」、示範題），改完重組。模擬卷它拿不到九成，就還沒完成：再開一個新的子代理重驗，最多驗 3 次；第 3 次還不到，把卡住的題型和導讀頁缺的地方列給使用者。

完成條件：上面每一項都做過；零基礎讀者在模擬卷拿到九成，或缺口已經列給使用者。

## 6. 交付

產出放在課程 repo 的指令檔或 README 說的位置；沒說就跟著同類產出（之前的導讀頁、作業檔）放；都看不出來就放在題目或課件所在的資料夾，交付時說放在哪。原始 HTML、截圖、翻譯檔、計算腳本收在那裡的 `tutor/` 底下，組好的頁面放在 `tutor/` 旁邊。

最後跟使用者說：先讀哪個檔、大約要讀多久、答案紙在哪、交之前要做什麼（印、簽名、檔名）、模擬卷在哪和什麼時候做（讀完並做完練習頁的隔天）。有練習頁時再說：練習頁在哪、基本功在頁面上就能對答案、整題寫完打開範本答案照給分點自評、全部做完按「複製填答結果」貼回來、卡住就說 § 編號。
