使用者是 repo 的主人，很多做法是照 agent 的建議走的。這個 session 讓他看懂一樣東西**現在**怎麼運作、為什麼這樣，好在下一個決定前心裡有底。

參數：$ARGUMENTS

`<P>` 是 `${CLAUDE_PLUGIN_ROOT}/pages`。

產出是一頁臨時的解說頁（寫法見 `<P>/PAGE.md`）加對話。repo 裡什麼都不寫；解說中發現文件錯了，問使用者要不要改，要改就照 repo 的規定另外改。

## 1. 找到它

1. 照 `<P>/PAGE.md`〈來源〉找出文件放在哪裡。
2. 把參數對到程式裡的**入口**：使用者從哪裡觸發它（頁面、按鈕、API、排程、指令），以及它最後改了什麼（資料表、檔案、外部服務）。參數是頁面網址或截圖時，先找出渲染它的元件。參數是里程碑時，入口是它的票改到的功能。
3. 對不到、或對到不只一樣東西：列出候選，問使用者是哪一個。

完成條件：入口和終點各列成 `檔案:行`。

## 2. 追一遍

從入口追到終點：經過哪些模組、在哪裡分岔、哪些情況會停下來等人、出錯時怎麼辦。範圍大就分給子代理（`model: "sonnet"`），各自帶回附 `檔案:行` 的摘要。同時讀文件裡講它的章節和決定紀錄，找出「為什麼這樣做」和誰定的。

完成條件：入口到終點的每一步、每個分岔都有來源；文件和程式說法不同的地方另外記下。

## 3. 寫解說頁

照使用者問的取捨，常用的段落：

1. **一段話**：它是做什麼的、你會在哪裡看到它。
2. **怎麼運作**：流程圖，加一步一段的說明。
3. **在架構裡的位置**：碰到哪些模組、資料和外部服務，附架構圖。
4. **你能控制什麼**：設定、開關、需要你按的地方。
5. **為什麼這樣**：相關決定，附決定者。
6. **限制和脆弱處**：已知會出錯的情況、沒測到的地方。
7. **改這裡會動到什麼**：想優化或重構它時要一起看的模組和測試。
8. **文件和程式對不上**。

參數裡的「想知道的事」放在最前面直接回答。

完成條件：照 `<P>/PAGE.md`〈交出前〉核對和渲染過。

## 4. 對話

在對話給解說頁的網址和完整路徑、三到五行的重點，以及〈文件和程式對不上〉的條數。然後：

- 照 `<P>/PAGE.md`〈交出後的對話〉；答案改變了頁上的說法就更新頁面。
- 有〈文件和程式對不上〉時，逐條問要不要修文件。

完成條件：〈文件和程式對不上〉的每一條都問過；使用者說看完了，server 已經關掉。
