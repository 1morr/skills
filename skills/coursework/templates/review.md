# 審查：成品對老師的原檔，一個角度

照以下輸入格式執行：

```
讀 <這個檔的完整路徑> 照做。
成品：<完整路徑>
角度：<要求與格式 | 逐題核對 | 版面>
課程資料夾：<完整路徑>
讀法：<一個檔的完整路徑>
不讀的路徑清單：<一個檔的完整路徑>
輸出檔：<完整路徑>
改了哪幾處（只審模式選填）：<改動清單或前後對照摘要>
```

你只審、只回報，不改任何課程或成品檔案；暫存檔和驗算腳本放在輸出檔所在資料夾。有填「改了哪幾處」時，重點細審這些改動本身是否正確、是否合乎讀法與格式，並追查它們對其餘段落、引用數字、表格與結論句的連鎖影響。

## 依據

判斷對錯只依課程資料夾裡老師發的原檔與「讀法」檔（照定案讀法審，不重新爭論；一般寫作偏好與個人常識不算依據）。先讀「不讀的路徑清單」，略過清單內所有路徑（待審成品本身除外）以及外部目錄與 git 歷史。

PDF 讀文字層（`pdftotext -layout -enc UTF-8` 或 `uv run --no-project --with pymupdf python`），核對 PDF 表格數據時開頁面圖對負號與併欄；docx 用 `uv run --no-project --with python-docx python` 檢查段落、表格與字級。

## 角度

只看 prompt 指定的那一個：

- **要求與格式**：把題目、評分指引、課程網站說明裡的每一項要求列成表，逐項在成品標出「做到 / 沒做到」與位置；字級、表格形式、檔名、長度等可量測項目實際量測；再逐條核對「讀法」是否落實。
- **逐題核對**：每一題的公式與課件是否一致（附頁碼）；代入數是否與原始數據吻合；把成品紙面上寫出的每條算式按顯示數字重算一次，檢查是否與紙面結果一致（抓中間值四捨五入造成的紙面算式矛盾）；結論句數字是否與算式結果一致；表格抽查頭、中、尾各幾列重算。
- **版面**：把成品渲染成逐頁圖片檢視：有無裁切、溢出、亂碼、跨頁表格缺表頭、或只剩一兩行的孤頁。本機無法渲染時照實寫，不猜。

## 分級

- **必須修**：答錯、與數據或依據不符、漏答、違反題目或讀法規定、紙面算式按不回去、或渲染損壞。每條附依據出處。
- **建議修**：改卷老師很可能誤會或扣分之處，寫明具體誤會方式與對應扣分項。
- **可不修**：其他，每條一行。

零條必須修、零條建議修屬正常結果，直接寫「可以交」。拿不準或說不出具體扣分依據的歸入可不修。

## 輸出

寫進輸出檔：一句結論；必須修、建議修每條寫位置、成品原文、問題依據或後果、最小改法；可不修每條一行；最後列出查核總數（要求幾項、算式幾條、表格幾列）。

最後一則訊息只寫輸出檔路徑和一句：必須修、建議修各幾條。輸出檔寫不進去時把報告全文放在最後一則訊息。
