你在主對話做這份作業。這個 skill 擋的是一種錯：一開始就把題目讀錯，之後的成品和每一輪審查都建立在這個讀法上。你讀過對話、聽過使用者的轉述，所以你的讀法不能當檢查；檢查交給**盲**的子代理，它們只看老師的原檔。

參數：使用者呼叫本 skill 時附帶的內容。

子代理範本在同目錄的 `templates/` 底下。每份範本各自開頭寫了給子代理的 prompt 格式：第一行填範本自己的完整路徑，其餘只填路徑和使用者的原話。

## 選哪一條路

每次叫用先讀這份評核的 `coursework/紀錄.md`（有的話），再看使用者要什麼：

- **從頭做一份**：照〈0. 定位〉到〈5. 收尾〉。`紀錄.md` 寫了做到哪一步，就從那一步接著做。
- **開放式／視覺設計作業或外部版本比較**（海報、簡報、開放式報告、隊友草稿、舊版）：完成〈1. 盲讀〉拍板讀法後，讀 [VARIANTS.md](VARIANTS.md) 探索方向或比較多版，定版後接回〈4. 驗證〉與〈5. 收尾〉。一般有固定做法的作業不讀它。
- **只審現有成品**（他自己做的、他改過的、別處做的）：讀 [REVIEW-ONLY.md](REVIEW-ONLY.md)。

## 老師的原檔、封存與讀檔規範

整份流程靠這條界線：

- **老師的原檔**：從課程網站下載、內容沒動過的檔（題目、評分指引、課件、例題與答案、統計表、數據），逐字抄下課程網站頁面文字的檔，課本，題目指定的原始數據來源。
- **我們的東西**：對話、使用者的轉述、成品和草稿、處理過的數據檔、`coursework/` 資料夾、學習紀錄、筆記、導讀頁、日程、git 歷史。分不出是誰的檔算我們的，列進身份卡問使用者。

盲的子代理只讀老師的原檔。給它的 prompt 只放路徑和使用者指認作業的原話，材料給整個課程的資料夾讓它自己找；你的讀法、對這份作業的描述、挑過的課件都不放進 prompt。

- **現成的成品封存到最後**：評核資料夾裡已經有這份作業的成品或草稿時，在新成品做完並驗證前，你和每個子代理都不打開它，身份卡只憑檔名、大小、日期記一列並放進「不讀的路徑清單」。它可能是照錯的讀法做的，先看過就會跟著讀；新成品驗證完才打開對比（使用者指定從它改起時改走 [REVIEW-ONLY.md](REVIEW-ONLY.md)）。
- **專案指令檔檢查**：子代理啟動時就會讀到專案指令檔。指令檔裡有講這份作業的讀法或答案時，先把那幾句原文列給使用者，問要不要搬進這份評核的 `coursework/讀法.md`，搬完再開子代理。
- **PDF 與表格讀取規範**（主對話與子代理共用）：
  1. **PDF 文字層與白色字**：優先讀文字層（機器上有 `pdftotext` 就用 `pdftotext -layout -enc UTF-8`，否則用 `uv run --no-project --with pymupdf python` 呼叫 PyMuPDF `get_text`），抓出投影片畫面上看似空白的白色隱藏字；純掃描檔無文字層時轉逐頁圖閱讀。
  2. **表格數字開頁面圖核對**：從 PDF 表格取數時，除文字層外必渲染該頁圖片逐格核對負號、小數點與併欄對齊（文字層常漏掉負號或把相鄰欄併在一起）。

## 紀錄

這份評核的資料夾底下開 `coursework/`，寫進去的字照專案指令檔的規定：

- `紀錄.md`：身份卡、做到哪一步、計畫、驗證結果、等使用者決定的事。每次叫用先讀它，有就從上次停下的地方接著做。
- `讀法.md`：定案的讀法（含課件依據預設採用與使用者拍板的項目），一條一列：原文（檔名、頁碼）、採用的讀法、其他讀法或出處、定案日期與依據（預設採用／使用者拍板）。
- `sheets/`：比對完才把各張讀法單從暫存目錄搬進來留底。

盲讀進行中，讀法單都放本次對話的暫存目錄（沒有就用 `mktemp -d` 建在 repo 外）、一張一個子資料夾，子代理才看不到彼此的。

## 0. 定位

1. 讀專案指令檔：材料放哪、課程網站怎麼開、寫檔與別家模型盲讀有什麼規定。
2. 開 **1 個快速子代理**（如 Sonnet / Flash 級）做語意定位、擷取大綱評核段落與核對數據涵蓋期間，prompt 照 [locate.md](templates/locate.md)。主對話不重複掃描本機檔案。
3. **核對課程網站**（僅當專案指令檔寫了課程網站怎麼開時執行）：用瀏覽器自動化工具打開這份作業和所屬單元的頁面，抄下標題、截止時間、說明文字原文；列出網站上每個檔（題目、課件、例題、解答、數據）的檔名和大小，與子代理回報的本機清單逐一比對，標出本機缺少或大小不同的檔案。
4. 寫**身份卡**，每一列附原文和出處，寫進 `紀錄.md`：

   | 列 | 本機 | 課程網站 |
   | --- | --- | --- |
   | 科目、評核名稱、作業頁標題 | | |
   | 截止時間、交件方式、檔名規定 | | |
   | 佔分、個人或小組、長度限制 | | |
   | 老師的檔（題目、評分指引、示範、數據）：檔名、大小、日期 | | |
   | 數據的來源和期間（題目原文那一句） | | |
   | 這份評核對 GenAI 的規定（原文） | | |
   | 課程網站有、本機沒有或大小不同的檔 | | |
   | 名字相近的其他檔（別的年份、別的版本、相鄰的作業） | | |
   | 資料夾裡我們的東西（之後列進「不讀的路徑」） | | |

   課程網站那一欄未設定或讀不到就寫原因；本機和課程網站不一致的列標出來。
5. 題目候選有兩個以上分不出哪一份、本機與課程網站的截止時間不一致，或課程網站有本機缺少／大小不同的檔：把身份卡貼給使用者，停下來問。要下載的檔逐一列檔名、來源、大小，經使用者同意才下載；盲讀要等老師的原檔齊全才開。若題目明確且檔案齊全，直接做〈1. 盲讀〉，身份卡留到那一步和讀法一起交給使用者過目。

完成條件：身份卡每一列都有值或「找不到」，寫進了 `紀錄.md`；題目候選分歧與遠端缺檔都已由使用者確認補齊（或確認不需下載）。

## 1. 盲讀

1. **建立不讀清單與封存你的讀法**：在暫存目錄寫「不讀的路徑清單」（一行一個完整路徑：身份卡最後一列的學生檔案、`coursework/`、其他作業成品與草稿、學習紀錄、筆記、導讀頁；與老師原檔混在同一資料夾時逐檔列）。同時照 [read.md](templates/read.md) 的十一欄寫你自己的一張讀法單存到暫存目錄——必須在打開任何一張盲讀單之前寫完鎖定，之後不改。
2. **開 1 個高階推理子代理做同模型盲讀**（如 Opus / Pro 級），prompt 照 [read.md](templates/read.md)，單次完整涵蓋題目、評分與示範填滿十一欄。
3. **別家模型的盲讀者（選配）**：專案指令檔指定了別家 agent 和模型時，與第 2 步平行讀 [ORCA-READER.md](ORCA-READER.md) 派發外部盲讀 worker；未指定時跳過。
4. **誤讀防護**：每張盲讀單回來先查第 11 欄「讀過的檔」。只要讀到了我們的東西，那一張單作廢：**先把誤讀的那個學生檔案補進「不讀的路徑清單」**，再開一個新的子代理重讀。
5. **主對話比對與兩級分流**：鎖定你自己的讀法單後，直接與盲讀單逐欄對照（含各單第 8、9、10 欄項目），凡做法不同會改變成品處，逐一打開老師原檔核實管這件事的原文、檔名與頁碼，分為兩級：
   - **預設採用讀法（課件或老師示範已有依據）**：原文、課件或老師同類示範已有明確做法或慣例時，直接列為預設採用並附上檔名與頁碼出處（你的讀法與盲讀單不同而原文支持盲讀單時，照盲讀單修正並註明你原本怎麼讀），交使用者過目即可，直接放行。不影響成品的課件筆誤亦單列備查。
   - **真歧義與缺漏（須使用者拍板）**：僅當原檔、課件與老師示範皆無慣例可循，且不同讀法會實質改變答案數值或繳交結構時，才列為待決問題。每一題用白話寫清：問什麼（術語補一句白話）、照各讀法成品差在哪、你的建議和理由（建議僅依題目原文、老師示範與盲讀單；若屬漏給參數或數據範圍等原文定不了的事，建議問老師並附可直接寄出的草稿，同時說明等回覆期間先採哪個暫行值與日後改哪裡）。
6. **回報與確認**：用一則訊息依序給出身份卡、「預設採用讀法（附出處）」清單、待決的真歧義（有的話），並順帶問一次是否有不在檔案裡的要求（課堂補充、公告、email）。
   - 有待決真歧義時向使用者提問（有互動提問工具就用它，建議選項放第一個）：**使用者明確回覆「照建議」時，即記錄授權採用建議讀法並放行**；使用者表示沒看懂題意時才換白話補釋。
   - 若零真歧義且無影響成品的缺漏，將身份卡與預設採用讀法寫入 `讀法.md` 並貼出摘要後直接放行進入〈2. 計畫〉。
7. 定案的讀法（含預設採用與使用者拍板／授權項目）全部寫進 `coursework/讀法.md`；各張讀法單搬進 `coursework/sheets/`。

完成條件：所有讀法單已查證原文並歸檔至 `coursework/sheets/`；預設採用讀法（附出處）與所有真歧義／缺漏的使用者決定（含「照建議」授權或等老師回覆的暫行值）均已寫入 `讀法.md`。

## 2. 計畫

照 `讀法.md` 和老師的原檔寫入 `紀錄.md`：

- **要求清單**：題目和評分指引的每一項要求一列，對到成品的哪一段。
- **步驟表**：每一步一列：做什麼、用什麼工具、老師在哪份檔哪一頁教的、這一步的產出。做法、工具、符號、格式都照老師教的和示範的。
- **對不到出處的步驟**：老師原檔沒教、不用就做不出來的步驟，單獨列出並附題目原文。
- 成品的形式、位置，以及做完怎麼輸出成可視畫面。

**條件式核可**：僅當「對不到出處的步驟」**非空**時，才把計畫與無出處步驟貼給使用者，停下來等他核可；若每一步都對得到老師原檔出處，寫入 `紀錄.md` 後直接進入〈3. 製作〉。

完成條件：每一項要求在步驟表都有對應步驟並寫入 `紀錄.md`；每一步都有出處，或「對不到出處的步驟」已獲使用者核可。

## 3. 製作

成品只做一版（開放式作業或多版比較見 [VARIANTS.md](VARIANTS.md)），在主對話照步驟表做：

- **PDF 白色字與表格頁圖核對**：讀取課件公式、例題與 PDF 表格數據時，照〈老師的原檔、封存與讀檔規範〉讀文字層抓投影片白色字，並打開 PDF 頁面圖逐格核對表格負號、小數點與併欄。
- **算出來的數字由一支計算腳本算**，成品由腳本從這些數字產生，不手抄。老師有同一個方法的例題答案時，腳本先套在例題上，完全對上才算正式題目（對不上表示公式或初始值規定理解有誤）。
- **寫出來的算式要按得回去**：成品上每一條代入數字的算式，直接拿紙面上寫出的顯示數字重算，必須得到紙面上寫的結果。中間值帶全精度、顯示時四捨五入最容易出錯（紙面出現 `368.0 + 35.6 = 403.7`），因此代入的數要比結果多留幾位小數，並寫一支驗算腳本把成品上每條顯示算式重算一次。
- **同步產出分題 `answer.html`**：分題作答／文字數值報告類作業，建置腳本必同步產出 `coursework/out/answer.html`，文字與繳交檔一致，每題包在 `<div class="part" data-part="a">…</div><!--/part-->` 裡（海報、簡報、純程式專案豁免）。
- 原始檔與腳本放 `coursework/src/`，產出放 `coursework/out/`（封存的舊成品留在原位不動）。遇到材料未涵蓋或要求與示範衝突的計畫外狀況，附原文停下來問。
- 做完輸出成可視畫面，自己逐頁看一遍；本機渲染不了的格式（例如沒有 Word）照實記錄，交件前請使用者打開確認。

完成條件：要求清單每一項在成品上指得出位置；計算腳本通過例題驗算；成品每條顯示算式都按得回去；應附帶的 `coursework/out/answer.html` 已同步產出；產出已逐頁看過（或寫明哪一部分本機無法渲染）。

## 4. 驗證

依作業型態分流派發高階推理子代理（如 Opus / Pro 級）；`coursework/` 在不讀清單上，把 `讀法.md`（與審查用的成品）複製到暫存目錄再交給子代理：

1. **派發驗證子代理**：
   - **量化計算／有標準答案的作業**：平行開 **1 個盲做子代理**（prompt 照 [redo.md](templates/redo.md)，計算腳本一過例題驗算即可啟動）與 **2–3 個審查子代理**（prompt 照 [review.md](templates/review.md)，平行跑 `要求與格式`、`逐題核對`；成品渲染得出來時加跑 `版面`）。
   - **無計算的開放式作業**（純申論、海報、簡報等無數值計算與標準答案者）：**直接跳過 [redo.md](templates/redo.md) 與 `逐題核對`**，只開 `要求與格式`（及可渲染時 `版面`）。從 [VARIANTS.md](VARIANTS.md) 路徑二定版過來的，照該檔規定只驗合併處與計算題。
2. **對比盲做**（有跑時）：盲做答案表每一列和成品對應答案比，差距在顯示位數以內算一致。不一致時由你重算並翻原文判斷誰對；屬讀法分歧造成的，連同原文交給使用者，不自行裁定。盲做回報的「讀法和原文對不上」每一條都轉交使用者。
3. **查證審查意見**：每一條親自查（數字重算、引用翻原文、版面看渲染圖），結果只有**採納**（附證據）或**駁回**（附理由）。只改採納的「必須修」和「建議修」，取最小改動並重建（含同步更新 `answer.html`）；改法若會動到 `讀法.md`，先向使用者講清改動前後差異，獲同意後連 `讀法.md` 一起改。採納了「必須修」才對受影響的角度重審一輪。
4. **打開封存的舊成品**（有的話，這時才開）：逐題比答案和做法，差異列成表（新成品照哪條讀法、舊版哪裡不同），留哪一份由使用者決定。
5. 回報：盲做幾個答案一致（若有）、審查採納和駁回各幾條（駁回的每條一句理由）、和舊成品的差異、交件前使用者要自己做的事。

完成條件：應跑的盲做與審查角度皆已核實完畢（每條意見皆標採納或駁回，必須修已修畢重驗）；封存舊成品（若有）已完成比對；結果記進 `紀錄.md`。

## 5. 收尾

- 封存的舊成品：使用者決定不留時，移到系統垃圾桶，不直接刪。
- 確認分題作答／文字數值報告類作業的建置腳本已同步更新 `coursework/out/answer.html`，每題包在 `<div class="part" data-part="a">…</div><!--/part-->` 裡（海報、簡報、純程式專案豁免）。
- `紀錄.md` 補上：成品在哪、怎麼重建、驗證結果、交件前使用者要自己做的事。
- 給使用者交件清單：哪個檔、怎麼印或上傳、截止時間、交到哪。
- 附一行提示：需要學這份作業的做法或備考複習時，可手動執行 `/tutor`。
