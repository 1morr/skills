你在主對話做這份作業。這個 skill 擋的是一種錯：一開始就把題目讀錯，之後的成品和每一輪審查都建立在這個讀法上。你讀過對話、聽過使用者的轉述，所以你的讀法不能當檢查；檢查交給**盲**的子代理，它們只看老師的原檔。

目前做到計畫核可為止；製作、驗證、教學頁還沒寫進這份 skill，計畫核可後照〈3. 之後〉說明。

參數：$ARGUMENTS

`<T>` 是 `${CLAUDE_SKILL_DIR}/templates`。三份範本各自開頭寫了給子代理的 prompt 格式：第一行的路徑填範本自己的完整路徑，其餘只填路徑和使用者的原話。

## 老師的原檔和我們的東西

整份流程靠這條界線：

- **老師的原檔**：從課程網站下載、內容沒動過的檔（題目、評分指引、課件、例題與答案、統計表、數據），逐字抄下課程網站頁面文字的檔，課本，題目指定的原始數據來源。
- **我們的東西**：對話、使用者的轉述、成品和草稿、處理過的數據檔、`coursework/` 資料夾、學習紀錄、筆記、導讀頁、日程、git 歷史。分不出是誰的檔算我們的，列進身份卡問使用者。

盲的子代理只讀老師的原檔。給它的 prompt 只有路徑和使用者指認作業的原話：你的讀法、對這份作業的任何描述、挑過的「相關課件」都不寫進去，材料給整個課程的資料夾，讓它自己找。

子代理一開始就會讀到專案指令檔。指令檔裡有講這份作業的讀法或答案時，先把那幾句原文列給使用者，問要不要搬到這份評核的 `coursework/讀法.md`，搬完再開子代理。

## 紀錄

這份評核的資料夾底下開 `coursework/`，寫進去的字照專案指令檔的規定：

- `紀錄.md`：身份卡、做到哪一步、計畫、等使用者決定的事。每次叫用先讀它，有就從上次停下的地方接著做。
- `讀法.md`：使用者拍板的讀法，一條一列：原文（檔名、頁碼）、選了什麼、其他讀法、哪一天拍板。
- `sheets/`：比對完才把各張讀法單和差異表從 scratchpad 搬進來留底。

盲讀進行中，讀法單都放 scratchpad、一張一個資料夾，子代理才看不到彼此的。

## 0. 定位

1. 讀專案指令檔：材料放哪、課程網站怎麼開、寫檔有什麼規定。
2. 開定位子代理（`model: "sonnet"`），prompt 照 `<T>/locate.md`。
3. 它在找的時候，你自己也找一次題目檔、評分指引、老師的示範、數據。專案指令檔寫了課程網站怎麼開時，用瀏覽器自動化工具打開這份作業的頁面，抄下標題、截止時間、說明文字的原文、每個附檔的名稱和大小。
4. 寫**身份卡**，每一列附原文和出處，寫進 `紀錄.md`：

   | 列 | 本機 | 課程網站 |
   | --- | --- | --- |
   | 科目、評核名稱、作業頁標題 | | |
   | 截止時間、交件方式、檔名規定 | | |
   | 佔分、個人或小組、長度限制 | | |
   | 老師的檔（題目、評分指引、示範、數據）：檔名、大小、日期 | | |
   | 數據的來源和期間（題目原文那一句） | | |
   | 這份評核對 GenAI 的規定（原文） | | |
   | 名字相近的其他檔（別的年份、別的版本、相鄰的作業） | | |
   | 資料夾裡我們的東西（之後列進「不讀的路徑」） | | |

   課程網站那一欄讀不到就寫讀不到和原因。本機和課程網站不一樣的列標出來。
5. 定位子代理、你、課程網站三邊對「題目是哪個檔」「截止時間」「附檔有哪些」有任何不一致：把身份卡貼給使用者，停下來問。三邊一致就接著做〈1. 盲讀〉，身份卡留到那一步和讀法一起給使用者確認。

完成條件：身份卡每一列都有值或「找不到」，寫進了 `紀錄.md`；三邊的不一致都問過使用者。

## 1. 盲讀

1. **先封存你的讀法**：照 `<T>/read.md` 的十一欄寫你自己的一張，存到 scratchpad。開盲讀之前寫完，之後不改：看過別人的再寫，就分不出哪些是你原本的讀法。
2. **開三個盲讀子代理**（`model: "opus"`，同一則訊息送出），prompt 照 `<T>/read.md`，三個的入口分別是 `題目`、`評分`、`示範`。「不讀的路徑」填身份卡最後一列，加上專案裡其他我們的東西所在的資料夾。
3. 每張單回來先看「讀過的檔」：讀到我們的東西的那一張作廢，重開一個。
4. **匿名比對**：把四張單（三張盲讀加你的）複製到同一個資料夾，檔名改成 `A.md` 到 `D.md`，順序打亂，對應記在 `紀錄.md`。開比對子代理（`model: "opus"`），prompt 照 `<T>/compare.md`。
5. **差異表原樣交給使用者**：不刪列、不合併、不標推薦。你帶著對話裡的讀法，由你裁定等於沒比。用一則訊息依序給：
   - 身份卡。
   - 差異表的每一列：原文、各讀法、照各讀法做出來成品差在哪。
   - 單子上「材料裡找不到」和「要求和示範不一致」的每一條，附原文。
   - 問一次：有沒有不在檔案裡的要求（課堂上說的、公告、email）。有截圖或原文就請他放進材料資料夾。

   再用 AskUserQuestion 逐條問讀法，選項照 A 到 D 的順序，每個選項寫那種讀法和它的後果。一條讀法會改變整份成品、原文又定不了時，多給一個選項「問老師」，並附一封可以直接寄的草稿。
6. 使用者的每個決定寫進 `讀法.md`；四張單和差異表搬進 `coursework/sheets/`。

完成條件：差異表的每一列、每一條「找不到」和「不一致」，在 `讀法.md` 都有使用者的決定，或寫明在等老師回覆；身份卡使用者確認過。

## 2. 計畫

照 `讀法.md` 和老師的原檔寫，存進 `紀錄.md`：

- **要求清單**：題目和評分指引的每一項要求一列，對到成品的哪一段。
- **步驟表**：做這份成品的每一步一列：做什麼、用什麼工具、老師在哪份檔哪一頁教的、這一步的產出。做法、工具、符號、格式都照老師教的和他示範的。
- **對不到出處的步驟**：老師的原檔沒教、不用就做不出來的，單獨列出、附題目原文，問使用者。
- 成品的形式和位置，做完怎麼輸出成看得到的樣子。

把計畫貼給使用者，等他核可。

完成條件：每一項要求在步驟表有對應的步驟；每一步有出處，或在「對不到出處」裡而且使用者回答了；使用者核可了計畫。

## 3. 之後

計畫核可後，照計畫在主對話做成品，做完告訴使用者：這份 skill 還沒有驗證和教學頁的步驟，成品沒有經過盲做對比。
