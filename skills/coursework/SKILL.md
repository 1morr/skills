你在主對話做這份作業。這個 skill 擋的是一種錯：一開始就把題目讀錯，之後的成品和每一輪審查都建立在這個讀法上。你讀過對話、聽過使用者的轉述，所以你的讀法不能當檢查；檢查交給**盲**的子代理，它們只看老師的原檔。

參數：$ARGUMENTS

`<T>` 是 `${CLAUDE_SKILL_DIR}/templates`。每份範本各自開頭寫了給子代理的 prompt 格式：第一行的路徑填範本自己的完整路徑，其餘只填路徑和使用者的原話。

## 選哪一條路

每次叫用先讀這份評核的 `coursework/紀錄.md`（有的話），再看使用者要什麼：

- 從頭做一份：照〈0. 定位〉到〈6. 收尾〉。`紀錄.md` 寫了做到哪一步，就從那一步接著做。
- 審一份已有的成品（他自己做的、他改過的、別處做的）：照〈只審〉。

## 老師的原檔和我們的東西

整份流程靠這條界線：

- **老師的原檔**：從課程網站下載、內容沒動過的檔（題目、評分指引、課件、例題與答案、統計表、數據），逐字抄下課程網站頁面文字的檔，課本，題目指定的原始數據來源。
- **我們的東西**：對話、使用者的轉述、成品和草稿、處理過的數據檔、`coursework/` 資料夾、學習紀錄、筆記、導讀頁、日程、git 歷史。分不出是誰的檔算我們的，列進身份卡問使用者。

盲的子代理只讀老師的原檔。給它的 prompt 只有路徑和使用者指認作業的原話：你的讀法、對這份作業的任何描述、挑過的「相關課件」都不寫進去，材料給整個課程的資料夾，讓它自己找。

**現成的成品封存到最後**：評核資料夾裡已經有這份作業的成品或草稿時，在新的成品做完之前，你和每個子代理都不打開它，身份卡上只憑檔名、大小、日期記一列。它可能是照錯的讀法做的，先看過就會跟著它讀。新的成品做完才拿它來對比；使用者說要從它改起時才提前打開。

子代理一開始就會讀到專案指令檔。指令檔裡有講這份作業的讀法或答案時，先把那幾句原文列給使用者，問要不要搬到這份評核的 `coursework/讀法.md`，搬完再開子代理。

## 紀錄

這份評核的資料夾底下開 `coursework/`，寫進去的字照專案指令檔的規定：

- `紀錄.md`：身份卡、做到哪一步、計畫、等使用者決定的事。每次叫用先讀它，有就從上次停下的地方接著做。
- `讀法.md`：使用者拍板的讀法，一條一列：原文（檔名、頁碼）、選了什麼、其他讀法、哪一天拍板。
- `sheets/`：比對完才把各張讀法單和差異表從 scratchpad 搬進來留底。

盲讀進行中，讀法單都放 scratchpad、一張一個資料夾，子代理才看不到彼此的。

## 0. 定位

1. 讀專案指令檔：材料放哪、課程網站怎麼開、寫檔有什麼規定。
2. 開定位子代理（`model: "sonnet"`），prompt 照 `<T>/locate.md`。
3. 它在找的時候，你自己也找一次題目檔、評分指引、老師的示範、數據。專案指令檔寫了課程網站怎麼開時，用瀏覽器自動化工具打開這份作業的頁面，抄下標題、截止時間、說明文字的原文。再列出課程網站上這份作業和它那個單元的每個檔（題目、課件、例題、解答）的檔名和大小，和本機逐一比：本機沒有的、大小不同的都記下來。老師常在作業發佈後才放出解答檔，本機的副本也可能被改過。
4. 寫**身份卡**，每一列附原文和出處，寫進 `紀錄.md`：

   | 列 | 本機 | 課程網站 |
   | --- | --- | --- |
   | 科目、評核名稱、作業頁標題 | | |
   | 截止時間、交件方式、檔名規定 | | |
   | 佔分、個人或小組、長度限制 | | |
   | 老師的檔（題目、評分指引、示範、數據）：檔名、大小、日期 | | |
   | 數據的來源和期間（題目原文那一句） | | |
   | 這份評核對 GenAI 的規定（原文） | | |
   | 課程網站有、本機沒有或大小不同的檔 | | |
   | 名字相近的其他檔（別的年份、別的版本、相鄰的作業） | | |
   | 資料夾裡我們的東西（之後列進「不讀的路徑」） | | |

   課程網站那一欄讀不到就寫讀不到和原因。本機和課程網站不一樣的列標出來。
5. 定位子代理、你、課程網站三邊對「題目是哪個檔」「截止時間」有任何不一致，或課程網站有本機缺的、大小不同的檔：把身份卡貼給使用者，停下來問。要下載的檔逐一列檔名、來源、大小，使用者同意才下載；盲讀要等老師的檔齊了才開，缺了解答檔的盲讀者讀不到老師的示範。三邊一致、檔也齊，就接著做〈1. 盲讀〉，身份卡留到那一步和讀法一起給使用者確認。

完成條件：身份卡每一列都有值或「找不到」，寫進了 `紀錄.md`；三邊的不一致都問過使用者；課程網站上這個單元的每個檔，本機都有而且大小相同，或使用者說了不用。

## 1. 盲讀

1. **封存你的讀法**：照 `<T>/read.md` 的十一欄寫你自己的一張，存到 scratchpad。可以在盲讀子代理跑的時候寫，但要在打開任何一張盲讀單之前寫完，之後不改：看過別人的再寫，就分不出哪些是你原本的讀法。
2. **開三個盲讀子代理**（`model: "opus"`，同一則訊息送出），prompt 照 `<T>/read.md`，三個的入口分別是 `題目`、`評分`、`示範`。「不讀的路徑清單」是 scratchpad 裡的一個檔，一行一個完整路徑：課程資料夾裡每一樣我們的東西（身份卡最後一列、其他作業的成品和草稿、學習紀錄、筆記、導讀頁）。老師的檔和我們的東西在同一個資料夾時逐檔列。
3. **別家模型的盲讀者**（專案指令檔寫了用哪個 agent 和模型才開，和第 2 步同時開）：同一個模型的幾個子代理會一致地讀錯，換一家模型才擋得住。
   - 呼叫 Skill 工具載入 `orchestration`。把和第 2 步一樣的 prompt（入口 `題目`）寫成 scratchpad 裡的一個檔，再跑 `orca orchestration worker-start --spec-file <那個檔> --task-title <標題> --worktree path:<課程 repo 的路徑> --agent <agent> --model <模型>`。
   - 之後照常做你的事；Orca 會送一行訊息叫你跑 `orca orchestration check --run <run id>`，回報的 `reportPath` 就是它的讀法單。
   - 使用者在畫面上只看得到「有一則訊息」：每次送出和收到，在對話寫一行，對誰、送了或收到什麼、檔案的完整路徑。
   - Orca 沒在跑、worker 起不來，或它比最慢的子代理多花一倍時間還沒回報：告訴使用者，先用已經回來的單比對。
4. 每張單回來先看「讀過的檔」：讀到我們的東西的那一張作廢，重開一個。
5. **匿名比對**：把每一張單（盲讀的加你的）複製到同一個資料夾，檔名改成 `A.md`、`B.md`…，順序打亂，對應記在 `紀錄.md`。開比對子代理（`model: "opus"`），prompt 照 `<T>/compare.md`。
6. **差異表交給使用者決定**：不刪列、不合併。用一則訊息依序給：
   - 身份卡。
   - 差異表的每一列，用白話寫三件事：這是在問什麼（使用者可能不熟的詞補一句解釋）、照各讀法做出來成品差在哪、你的建議和理由。
   - 「材料裡找不到」和「要求和示範不一致」裡影響成品的每一條，同樣寫法；不影響成品的列成一份清單，每條一行，使用者看得到但不用回答。
   - 問一次：有沒有不在檔案裡的要求（課堂上說的、公告、email）。有截圖或原文就請他放進材料資料夾。

   **建議的依據**只有三樣：題目和指引的原文、老師實際的示範、盲讀單。你自己的讀法和多數盲讀單不同時，照盲讀單建議，並說出你原本怎麼讀：你帶著對話裡的理解，盲讀單沒有。原文定不了、又會改變答案的（沒給的參數、數據的範圍），建議是問老師，附一封可以直接寄的草稿，並說明等回覆期間先照哪個值做、之後改哪一處。

   再用 AskUserQuestion 逐條問，建議的選項放第一個；題目寫得讓只看到對話框的人也答得了。使用者回「不懂」「你決定」時，換一種講法再解釋一次那一條，請他對建議說好或不好：讀法要他看過才算定案。
7. 使用者的每個決定寫進 `讀法.md`；每張單和差異表搬進 `coursework/sheets/`。

完成條件：差異表的每一列、影響成品的每一條「找不到」和「不一致」，在 `讀法.md` 都有使用者的決定，或寫明在等老師回覆；身份卡使用者確認過。

## 2. 計畫

照 `讀法.md` 和老師的原檔寫，存進 `紀錄.md`：

- **要求清單**：題目和評分指引的每一項要求一列，對到成品的哪一段。
- **步驟表**：做這份成品的每一步一列：做什麼、用什麼工具、老師在哪份檔哪一頁教的、這一步的產出。做法、工具、符號、格式都照老師教的和他示範的。
- **對不到出處的步驟**：老師的原檔沒教、不用就做不出來的，單獨列出、附題目原文，問使用者。
- 成品的形式和位置，做完怎麼輸出成看得到的樣子。

把計畫貼給使用者，等他核可。

完成條件：每一項要求在步驟表有對應的步驟；每一步有出處，或在「對不到出處」裡而且使用者回答了；使用者核可了計畫。

## 3. 製作

成品只做一版，在主對話照計畫的步驟表做。

- **算出來的數字由一支計算腳本算**，成品由腳本從這些數字產生，不手抄。老師有同一個方法的例題答案時，腳本先套在例題上，對得上才算這一題：對不上表示公式或初始值抄錯了。
- **寫出來的算式要按得回去**：成品上每一條代入數字的算式，照紙上寫的數字重算，要得到紙上寫的結果。中間值帶全精度、顯示時四捨五入的成品最容易在這裡出錯（紙上是 368.0 + 35.6 = 403.7），所以代入的數比結果多寫幾位，並用一支腳本把每條算式重算一次。
- 原始檔放 `coursework/src/`，產出先放 `coursework/out/`：封存的舊成品還在原位，驗證完才決定哪一份留在評核資料夾。
- 遇到計畫外的事就停下來問，附原文：老師的材料沒涵蓋、不用沒教過的東西就做不出來、老師的要求和他實際的做法不一致。
- 做完輸出成看得到的樣子，自己逐頁看一遍。這台機器渲染不了的格式（例如沒有 Word）照實告訴使用者，交之前由他打開看。

完成條件：要求清單的每一項在成品上指得出位置；腳本過了例題驗算；成品上的算式每一條都按得回去；產出你逐頁看過，或寫明哪一部分看不到。

## 4. 驗證

1. **盲做**（`model: "opus"`，prompt 照 `<T>/redo.md`）：它只讀老師的原檔和 `讀法.md`，從頭算一次。`coursework/` 在不讀的路徑清單上，所以把 `讀法.md` 複製到 scratchpad 給它。計算腳本一過例題驗算就可以開，不用等成品排完。
2. **審查**（`model: "opus"`，prompt 照 `<T>/review.md`，一個角度一個子代理，同一則訊息送出）：`要求與格式`、`逐題核對`；成品渲染得出來時加 `版面`。成品複製到 scratchpad 再給它。
3. **對比盲做**：盲做答案表的每一列和成品的同一個答案比，差在顯示位數以內算一致。不一致的由你重算、打開原文判斷誰對；是讀法不同造成的，連同原文列給使用者，不自己裁定。它寫的「讀法和原文對不上」每一條都轉給使用者。
4. **查證審查意見**：每一條親自查，數字重算、引用打開原文、版面看渲染圖；結果只有採納（附證據）或駁回（附理由）。只改採納的必須修和建議修，用能消除問題的最小改動，改完重建。改法會動到 `讀法.md` 的某一條時，先問使用者（講清楚現在紙上是什麼樣、改了是什麼樣），他同意後連 `讀法.md` 一起改。採納了必須修才再審一輪，只開受影響的角度。
5. **打開封存的舊成品**（有的話，這時才開）：逐題比答案和做法，差異列成表：新的照哪一條讀法、舊的哪裡不同。哪一份留下由使用者決定。
6. 回報：盲做幾個答案一致、審查採納和駁回各幾條（駁回的每條一句理由）、和舊成品的差異、交之前使用者要自己做的事。

完成條件：盲做的每個答案都對過，不一致的都有結論或已交給使用者；審查的每一條都是採納或駁回；`紀錄.md` 記了這一步的結果。

## 5. 教學

教學只寫一次，寫在有上下文的地方：講這個範圍的 tutor 導讀頁裡這份作業的那一節。

1. 讓成品的建置腳本多出一份 `coursework/out/answer.html`：和要交的檔同樣的字，每一題包成 `<div class="part" data-part="a">…</div><!--/part-->`。導讀頁引的是它，頁上的答案就和交出去的一字不差。
2. 呼叫 Skill 工具載入 `tutor`，照它的 GUIDE.md〈做法導讀〉寫那一節，再照它的方式重建導讀頁，用瀏覽器自動化工具打開那一節看一次。
3. **照著重做**：開一個子代理（`model: "opus"`），prompt 照 `<T>/rebuild.md`：它只拿到導讀頁的原始檔和原始數據，照「自己從頭做一次」那一段逐步做。
   - 它做出來的每個答案和成品比。不一致時先查是頁面寫錯還是它做錯，頁面錯就改。
   - 它回報的「要猜的地方」「照字面做會錯的步驟」「沒先講就用到的詞」，改到照字面做得出來；「說不出為什麼的步驟」補上理由或指回講它的 §。改完重建，改動大就再跑一次。
4. 它不是真的新手：告訴使用者這一節在哪，請他照著做前兩三步，卡住就說是哪一步。

完成條件：照著重做的每個答案都和成品一致；它回報的每一條都改了，或寫明為什麼不改；對話裡有導讀頁的完整路徑和那一節的標題。

## 只審

- **成品是 `coursework/out/` 那一份改出來的**：呼叫 Skill 工具載入 `diff`，做 `out/` 的版本對使用者這一份的前後對照。改到的地方照〈4. 驗證〉第 2、4 步審（審查子代理的 prompt 多一行改了哪幾處）；整份再對一次 `讀法.md`，改動違反哪一條就附原文告訴使用者。算出來的數有變的，計算腳本和盲做的答案表要對得上新的數，對不上就是改錯了。
- **沒有 `讀法.md`**：先照〈0. 定位〉〈1. 盲讀〉做，這段期間你和子代理都不打開那份成品。讀法拍板後跳過計畫和製作，直接照〈4. 驗證〉：盲做的答案表和審查對的是使用者那一份。
- 動手改之前問使用者一次：由你改，還是只列出來讓他自己改。由你改時，原始檔照專案指令檔的規定改，每一條用能消除問題的最小改動。

完成條件：使用者改過的每一處都有結論（沒問題、建議改、違反哪一條讀法）；他要你改的都改了並重新驗過。

## 6. 收尾

- 封存的舊成品：使用者決定不留時，移到系統的垃圾桶，不直接刪。
- `紀錄.md` 補上：成品在哪、怎麼重建、驗證和教學的結果、交之前使用者要自己做的事。
- 交件清單給使用者：哪個檔、怎麼印或上傳、什麼時候、交到哪。
