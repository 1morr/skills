# 只審現有成品

審一份使用者已有的成品（自己做的、從 `coursework/out/` 改過的、或別處做好的）。

## 依有無既有讀法分流

- **成品是從 `coursework/out/` 那一版改出來的（已有 `coursework/讀法.md`）**：
  1. 載入 `diff` skill（用工具載入，或直接讀它的 `SKILL.md`），**走輕量純資料輸出分支（`--json-only` / 只取差異 JSON）**，將 `coursework/out/` 的版本與使用者改過的這一版比對輸出成暫存目錄下的 `diff.json`（保留 `.docx`、`.pdf`、`.html`、`.md` 段落與表格逐格比對，**不組 HTML 對照頁、不跑 `fill.py`，也不開瀏覽器截圖**）。
  2. 從 `diff.json` 整理改動清單，針對改到的地方照 [SKILL.md](SKILL.md)〈4. 驗證〉派發 [review.md](templates/review.md) 子代理審查（prompt 的「改了哪幾處」填入 `diff.json` 抽出的改動摘要），並整份再對一次 `coursework/讀法.md`：改動違反哪一條就附原文告訴使用者。
  3. 算出來的數值有變動的，核對 `coursework/src/` 計算腳本與先前盲做的答案表，並重算紙面顯示算式是否按得回去；對不上即代表改錯，列出正確算式與數值。

- **還沒有 `coursework/讀法.md`（全新的現有成品）**：
  1. 先把使用者這份成品封存進「不讀的路徑清單」，照 [SKILL.md](SKILL.md)〈0. 定位〉與〈1. 盲讀〉拍板 `讀法.md`——讀法拍板前，你和盲讀子代理都不打開這份成品，避免順著現成做法誤讀題目。
  2. `讀法.md` 定案後，跳過〈2. 計畫〉與〈3. 製作〉，直接照 [SKILL.md](SKILL.md)〈4. 驗證〉（依有無計算分流 [redo.md](templates/redo.md) 與 [review.md](templates/review.md)）對使用者這份成品執行驗證。

## 修改與交付

查證完所有審查意見後，動手改檔案之前問使用者一次：由你直接改，還是只列問題清單讓他自己改。由你改時，原始檔照專案指令檔規定用最小改動修補（若原有 `coursework/out/answer.html` 亦同步更新），改完針對受影響處重驗確認無誤。

完成條件：每一處改動或審查問題都有明確結論（沒問題、建議改、違反哪一條讀法或原文出處）；使用者要求代改的都已修妥並重驗通過。
