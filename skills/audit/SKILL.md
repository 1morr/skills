使用者是這些文件的作者，要知道哪裡該改，並在動手前核可每一項。這個 session 停兩次等他：交出**發現**、**執行**完。

參數：使用者呼叫本 skill 時附帶的內容。

標準是 mattpocock 的寫法：載入 `writing-for-agents` skill（用工具載入，或直接讀它的 `SKILL.md`），範圍裡有 skill 時連它的 `SKILL-MECHANICS.md` 一起讀；找不到就請使用者先裝。每條發現對到它的一個詞彙。

## 1. 範圍

1. 把參數對成檔案清單：每個 skill 的 `SKILL.md`、附屬 md、md 指到的腳本和範本、它們共用的檔；參數點名指令檔（`AGENTS.md` / `CLAUDE.md`）時，是它和它指到的文件。
2. 讀這些檔所在 repo 的指令檔和檢查（測試、lint、CI）：那個 repo 自己的規則優先於通用標準，已經有檢查守著的規則不再查。
3. 參數給了**對照組**（用過這個 skill 的專案、它的產出、對話紀錄）就列入：它驗文件寫的和實際發生的對不對得上。
4. md 是審查的對象，自己整份讀完。腳本、範本、測試只用來核對 md 說的對不對：超過約 30 個檔時分給快速子代理（如 Sonnet / Flash 級），要它列出 md 引用的參數、輸出、名稱和實際不同的地方，附兩邊的 `檔案:行號`；疑點由你回原檔查證後才算發現。

完成條件：清單上每份 md 你都讀過，其餘的檔你或子代理讀過。

## 2. 發現

這一段只讀。先直接回答參數裡問的事，再列發現。每條寫成 `檔案:行號` → 現在的寫法 → 問題（對應哪個詞彙）→ 改法，分三類，各自照你打算動手的順序排：

- **純改寫**：執行者的行為不變。
- **改行為**。
- **要使用者決定**：改名、刪除、合併 skill 或改叫用方式；有兩種合理做法的；理由查不清的。每題附建議。

已經夠好、不建議動的也列出來，各附一句原因。

- 建議刪掉一條告誡或已知行為之前，用 `git log -S` / `git blame` 查它當初為什麼加。理由已經消失的附那個 commit；查不到理由的、檔案不在 git 裡的，歸到「要使用者決定」。
- 建議改 repo 的規則時，同一條寫出要補或要刪的檢查，以及會紅和不該紅的例子各一個。
- 有對照組時，每條註明它在對照組裡實際發生過，還是讀文字推斷的；沒有對照組就在開頭說明全部是推斷。
- **改行為**的每一條註明能不能**試跑**：一個子代理在本次對話的暫存目錄（沒有就用 `mktemp -d` 建在 repo 外）裡跑得完的才能（不開 Orca 子 session、不必使用者在場）。能的寫出情境（一句話的任務和用到的輸入）和**預期**：改前和改後的產出差在哪；建議刪 no-op 時預期是「不變」。試跑哪幾條由使用者挑。

一個畫面放得下就寫在對話；放不下就寫成暫存目錄的一份 md，在對話給完整路徑、最值得做的幾件事、「要使用者決定」的每一題和建議。每個 skill 現在怎麼跑、各 skill 做法的對照，使用者問到才寫。

完成條件：參數裡問的事都答了；每條發現都有 `檔案:行號` 和分類，每條「改行為」都註明了能不能試跑；`git status` 沒有改動。交出後停下，等使用者回答。

## 3. 執行

照使用者的回答和發現的順序做，每步一個 commit（照那個 repo 的 commit 慣例）。新增檢查的那一步排最前面，後面的步驟才有東西守著。

- 搬動文字的步驟，commit 前確認搬走的每一段在新位置找得到。
- 不在 git 裡的檔：動手前複製一份到暫存目錄，告訴使用者路徑。
- 使用者挑了**試跑**的步驟，commit 之後跑：
  1. 取改前那一份：`git -C <repo> worktree add --detach <暫存目錄>/before-<步驟> HEAD~1`；不在 git 裡的檔用動手前的備份。
  2. 開兩個子代理，prompt 只差文件的完整路徑（改前、改後）：給同一個情境，要它照那份文件做，產出寫到暫存目錄各自的資料夾。確認文件裡的相對路徑或路徑縮寫能從該文件的實際位置正確解析；若有工具替換的變數或環境變數（如 `SKILLS_ROOT`），在 prompt 寫明各對應哪個資料夾。子代理使用與你這個 session 相同的模型：no-op 是相對模型說的，換一個模型跑的不算數。
  3. 兩邊的產出對照發現裡寫的預期。對得上就留著；對不上就 `git revert` 那個 commit，列為「沒做」，寫兩邊實際差在哪。
  4. 移除第 1 步的 worktree。

完成條件：每條發現不是 commit 了，就是列為「沒做」並寫了原因；試跑的每一步都寫了預期、改前和改後各看到什麼；那個 repo 的全部檢查在最後一個 commit 上通過；對話裡有 commit 清單、和發現不同的地方，以及每個動到的 repo 還沒 push 的 commit 數（`git log @{u}..` 算出來的；分支沒有 upstream 就寫沒有，改報它比預設分支多幾個 commit）。
